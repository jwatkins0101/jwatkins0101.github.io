DAY 1-2 Process Owner Interviews

Process Owner Interview Protocol

This is different from Phase 1 executive interviews. We're talking to the people who DO the work.

Opening (5 min): "We're here to understand exactly how [process] works today so we can design improvements. You're the expert—we need your help."
Current State Walkthrough (30 min)
  • Walk me through [process] step by step, from trigger to completion
  • What systems do you use at each step?
  • Where do you spend the most time?
  • What information do you need that's hard to get?
  • What are the most common errors or rework?
Exceptions & Edge Cases (15 min)
  • What happens when things don't go as planned?
  • What are the most common exceptions?
  • How do you handle [specific scenario]?
Pain Points & Wishlist (15 min)
  • If you could change one thing about this process, what would it be?
  • What would make your job easier?
Data & Inputs (15 min)
  • What data do you need to do this task?
  • Where does that data come from?
  • How reliable is it?

DAYS 5-7 Prototype Development

Prototype Build Focus

Day 5: Core functionality working end-to-end

Day 6-7: Polish, edge cases, demo-readiness

Prototype Completion Checklist

Functionality
  • Core use case works end-to-end
  • Handles most common variations
  • Edge cases identified and handled (or documented as limitations)
  • Error handling in place
  • Output is usable/readable
Demo Readiness
  • Clear "happy path" for demonstration
  • Sample data prepared for demo
  • Known limitations documented
  • Can run reliably (no crashes during demo)
Documentation
  • What it does (plain language)
  • How it works (technical summary)
  • What it needs to run (inputs, systems, data)
  • What would be needed to productionize
  • Known limitations

Prototype Guidelines

What Makes a Good Prototype

Criterion Standard
Functional Actually works—not a mockup or wireframe
Real data Uses actual company data (sanitized if needed) or realistic synthetic data
Core use case Solves the primary problem, not edge cases
Demo-able Can be shown and explained in 15-20 minutes
Documented Clear explanation of what it does and what's needed to productionize

What a Prototype Is NOT

Not This But This
Production-ready systemProof of concept
Handles all edge casesHandles the happy path
Polished UIFunctional output
Scalable architectureWorks for demonstration
Complete documentationSufficient to explain

Common Prototype Types

Opportunity Typical Prototype

Quality Gates

Before Prototype Demo

  • Prototype works end-to-end on happy path
  • Demo script prepared and practiced
  • Backup ready (screenshots/video) if live demo fails
  • Limitations documented and ready to explain
  • Productionization requirements documented

Before Deliverable Handoff

  • All 5 opportunity profiles complete
  • Economics validated and assumptions documented
  • Roadmap reviewed for realism
  • Investment plan complete with contingency
  • All documents consistent (no contradictions)
  • Executive summary stands alone
  • Presentation deck matches written deliverables

Risk Management

Common Phase 2 Risks

Risk Mitigation
Data access delayedRequest early; have fallback plan (synthetic data)
Prototype scope creepDefine "done" upfront; resist feature additions
Economics don't validateAdjust estimates early; document assumptions clearly
Prototype fails during demoAlways have backup; practice multiple times
Client expectations too highSet expectations in kickoff; emphasize "proof of concept"
Process more complex than expectedFocus on core use case; document complexity for implementation
